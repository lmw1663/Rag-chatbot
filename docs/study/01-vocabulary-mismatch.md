# 업무 용어와 단어 불일치 문제

> 공부용 노트. 관련 결정은 `CLAUDE.md`의 "도메인 컨텍스트"와 "설계 규칙"에 있다.

## 1. CLAUDE.md의 용어 목록은 누가 읽나

CLAUDE.md는 **개발할 때 Claude Code만 읽는 파일**이고, 완성된 챗봇은 읽지 못한다.
그래서 용어 목록이 하는 일은 두 가지로 나뉜다.

| 시점 | 읽는 쪽 | 역할 |
|---|---|---|
| 개발할 때 | Claude Code | 매뉴얼, 평가셋, 프롬프트를 같은 용어로 쓰게 함 |
| 챗봇이 동작할 때 | (CLAUDE.md는 안 읽힘) | 용어집을 쓰려면 매뉴얼이나 코드에 따로 넣어야 함 |

## 2. 개발할 때 쓰이는 곳

- **매뉴얼 작성 (1일차)**: 어떤 문서는 "튀김기", 어떤 문서는 "프라이어"라고 쓰면 검색 품질이 들쭉날쭉해진다. 표준 용어로 통일한다.
- **평가셋 작성 (3일차)**: 표준 용어로 묻는 질문과 다른 표현으로 묻는 질문을 섞는다.
  - 예: "프라이어 오일 교체 주기는?" / "튀김기 기름 언제 갈아요?"
- **프롬프트 작성**: 답변 문장에서도 표준 용어를 쓰도록 지시한다.

## 3. 챗봇이 동작할 때: 단어 불일치(vocabulary mismatch)

매뉴얼 원문:
> 크루는 프라이어 오일을 정해진 주기로 교체한다.

사용자 질문:
> 알바가 튀김기 기름 언제 갈아요?

뜻은 같지만 단어가 거의 겹치지 않는다.

- 임베딩은 의미를 벡터로 바꾸므로 동의어를 **어느 정도** 알아듣는다.
- 하지만 줄임말이나 현장 은어로 물으면 유사도 점수가 낮게 나올 수 있다.
- 점수가 "근거 없음" 임계값보다 낮으면, 매뉴얼에 답이 있는데도 **"매뉴얼에 없음"이라고 잘못 답한다.**

```
질문 → 임베딩 → 유사도 검색 → 점수 < 임계값 → "매뉴얼에 없음" (오답)
```

## 4. 해결 방법 세 가지

| 방법 | 방식 | 장점 | 단점 |
|---|---|---|---|
| A. 매뉴얼에 다른 표현 병기 | 문서에 "프라이어(튀김기)"처럼 적어 둠 | 가장 간단하고 코드 변경이 없음 | 매뉴얼을 쓸 때 계속 신경 써야 함 |
| B. 질문 변환 (query rewriting) | 임베딩 전에 용어집으로 "튀김기"를 "프라이어"로 바꾸거나 표준 용어를 덧붙임 | 검색 정확도를 직접 올림 | 용어집을 코드(`src/lib`)에 따로 관리해야 함 |
| C. 시스템 프롬프트에 용어집 | Claude가 용어를 이해하고 표준 용어로 답하게 함 | 답변 표현이 일관됨 | **검색 단계는 그대로**라 근본 해결이 아님 |

핵심 구분: **A와 B는 검색을 고치고, C는 답변을 고친다.** 검색이 실패하면 Claude에게 근거가 전달되지 않으므로 C만으로는 부족하다.

## 5. 이 프로젝트의 결정

1. 1일차: **A**로 시작한다. 매뉴얼에 표준 용어를 쓰고 다른 표현을 괄호로 병기한다.
2. 3일차: 평가셋에서 다른 표현으로 묻는 질문의 점수를 따로 본다.
3. 점수가 낮으면 **B**를 추가하고, 추가하기 전과 후의 점수를 기록한다.

면접에서 설명하는 흐름:
> "평가로 동의어 질문의 검색 실패를 발견했고, 질문 변환을 추가해 점수가 X에서 Y로 올랐다."
